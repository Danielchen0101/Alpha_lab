# Kalshi BTC 交易复盘（2026-07-26，美东时间）

## 结论

本次复盘只分析 AlphaLab 的 Kalshi Paper 账本，不包含任何真钱订单。权威来源是
`kalshi_robot_state/current` 中的 `realizedTradeRecords`、订单、成交、结算和逐周期研究快照。

当天两个市场合计盈利 **$86.61**，但两个机器人表现明显分化：

15 分钟机器人并不是“经常猜错”，而是**单次亏损的破坏力超过多次盈利**。其平均盈利市场约
$14.24，平均亏损市场约 -$41.37，盈亏比只有 0.34；在该盈亏结构下，保本胜率约为
74.4%，高于实际 72.2%。部分止盈还会把同一市场拆成多个盈利事件：当天 70 个分段实现事件
中有 62 个盈利、8 个亏损，但按完整市场归并后只有 13 胜 5 负。因此，事件胜率不能替代按
市场、按完整交易论点计算的损益。

## 主要亏损路径

1. **止损后快速反向重入**

   15 分钟 `...1830` 市场先买 YES、分段止盈并保护性平仓，113 秒后又反向买入 109 张 NO。
   32 秒后模型再次翻转，紧急平仓约造成 -$63.48；该市场最终约亏 -$73.94。这不是单一预测
   错误，而是同一短周期市场在噪声中重复开新论点。

2. **高价合约尾部风险不对称**

   `...2145` 以约 $0.87 买入 NO。单张最大盈利只有约 $0.13，失败时却可能损失约 $0.87，
   下行/上行约为 6.7:1。即使模型概率为 0.947，一次尾部错误也能吃掉多笔正常盈利；该市场
   最终约亏 -$58.29。

3. **风险预算按订单而不是按完整市场论点计算**

   原来的 `riskPerTradePct=0.75%` 约束单次下单，但加仓可以把同一 ticker 的总暴露逐步推到
   `maxSingleMarketExposurePct=8%`。因此页面上看似“小风险”的多笔订单，合并后可能是一个
   大仓位。

4. **加仓条件允许一项指标恶化**

   原逻辑是“概率改善 **或** 保守 edge 改善”即可加仓。一项变好会掩盖另一项变差。整点
   `...` 的一个亏损市场就在 edge 已恶化时仍增加了合约。

5. **弱质量信号和多重选择偏差**

   多个大亏市场的质量分数只有 41、44、53、55，模型概率约 0.60–0.65。整点扫描还会在约
   32 个 strike 中选最强者；如果不对候选数量做惩罚，最大值天然容易高估。

6. **行情时间语义不一致**

   研究流在每个 15 分钟结算窗口的最后一分钟会把 `price` 替换成 15 分钟结算平均价。整点
   扫描若在非整点的 `:14/:29/:44` 窗口复用该值，会把平滑结算价当作当前 BRTI。整点
   strike 评估应使用原始实时价格，只有真正的整点结算窗口才使用相应结算平均。

## 优化规则

### 1. 入场安全门

- 行情时间戳缺失或过期时 fail closed，不产生交易候选。
- 15 分钟入场采用安全下限：质量分、模型概率、保守 edge 和价格上限共同通过；用户配置只能
  比安全下限更严格，不能放宽安全底线。
- 当天样本的方向性筛选显示，`quality >= 55`、`model probability >= 0.64`、
  `conservative edge >= 0.0075`、`price <= 0.92` 能显著剔除坏交易。该结果属于当日
  in-sample 诊断，必须通过滚动样本和 Paper 前向验证，不能被当作未来收益保证。
- 高价、弱质量、接近截止时间和数据延迟分别产生可审计的仓位折扣；任一折扣都不能被另一项
  指标抵消。

### 2. 论点级仓位预算

推荐仓位以保守 edge 和二元合约 payout 计算的分数 Kelly 为起点，再应用以下硬上限：

```text
raw_kelly = max(0, (p_conservative - entry_price) / (1 - entry_price))
target_fraction =
    min(fractional_kelly * raw_kelly, per_thesis_cap)
    * signal_quality_multiplier
    * tail_price_multiplier
    * freshness_multiplier
contracts =
    floor(min(risk_budget, thesis_remaining_budget, event_remaining_budget)
          / max_loss_per_contract)
```

- `risk_budget` 以**当前环境的真实 equity**计算。
- `thesis_remaining_budget` 包括同 ticker 所有已成交仓位、在途订单和加仓，不按单笔重置。
- `event_remaining_budget` 聚合同一 BTC 结算事件的相关 strike，防止整点机器人在不同
  strike 上重复承担同一方向风险。
- 价格越接近 $1，尾部折扣越强；不能因为模型置信度高就消除最大损失不对称。

根据当天的尾部损失，默认上限已收紧为：单笔硬风险 0.50%、15% fractional Kelly、组合总
敞口 10%、单 ticker / 同一整点事件 2%。同方向加仓最多使用新计算仓位的 25%，两次加仓
至少间隔 90 秒。某环境当天的已实现亏损达到 equity 的 2% 后，新的买入和加仓停止；现有
仓位的 reduce-only 减仓、保护性退出和结算管理仍然允许。

### 3. 退出、重入与加仓

- 保护性或紧急止损后，同 ticker 在本结算周期内禁止重新开仓；结算后自然解除。
- 普通模型翻转也要经过至少 90 秒冷却，并要求新方向达到更高的二次确认门槛：模型概率至少为
  `max(入场下限 + 5 个百分点, 70%)`，保守 edge 至少为
  `max(入场下限 + 0.5 个百分点, 1.25%)`。Paper 决策与 Real 最终提交前都重复校验。
- 加仓必须同时满足：概率没有实质恶化、保守 edge 没有实质恶化，且两者至少一项超过最小
  改善幅度；`OR` 不能再掩盖恶化。
- 加仓后仍须重新通过 ticker 级、事件级、组合级风险预算。
- 已持有的整点 strike 必须先处理所有可成交的紧急退出、保护性退出和盈利减仓，再处理
  暂时无 bid 的紧急/保护仓位，最后才允许加仓或普通持有。无深度风险仓仍优先于任何加仓，
  但不能阻塞另一个实际可成交的风险退出。

### 4. Paper / Real 一致性与隔离

- Paper 和 Real 使用同一个无状态研究与策略引擎，差异仅限行情/账户/执行适配器。
- 选择 Paper 时，只读取 Paper 资金并写入 Paper 账本；选择 Real 时，以 Kalshi
  `balance + portfolio_value` 为 equity，并只发送 Real 订单。
- 环境切换必须停止机器人并要求用户在目标环境重新启用；页面 GET、轮询和预览不能隐式切换
  运行环境。
- 每次 Real 下单前重新读取持久状态，确认环境仍为 Real、机器人仍启用、arming 仍有效，
  防止旧 worker 在切换或停机后多发一单。
- Real 启停、模式切换、配置保存、连接测试、凭证删除和最终订单 POST 共用同一用户级持久
  fencing lease；持锁后还要绕过进程 TTL 缓存，直接读取最新持久凭证和状态，不能依赖
  进程内锁、旧快照或旧 API key。
- 最终 POST 前对余额、持仓和全部未完成订单执行分页完整的签名只读重取，再重新检查现金、
  当日亏损、组合/ticker/event 暴露以及手工仓位冲突；缺页、重复游标或资源不完整一律
  fail closed。日内损益由提前 SELL 与结算的实现记录幂等重算，不能漏掉止损亏损。
- Real 的 AlphaLab 展示账本以启用时的 `displayBaseline` 为起点，并只显示带 AlphaLab
  管理标记的订单/成交。Kalshi 账户原有历史不删除，Paper 历史完全不修改。
- 实盘成交按 Kalshi 当前 `outcome_side` 语义归一化；SELL 减少的是所持结果侧，不能继续按
  旧 action 语义计算 FIFO 和损益。
